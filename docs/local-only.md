# Local inference and memory

The companion keeps memory in a local SQLite database. Browser assets are bundled: no CDN, external font, analytics script, web search, cloud memory service, API-key field, or cloud fallback is included. The browser talks to the loopback application; Python talks to the configured loopback inference service.

The model adapter accepts only HTTP loopback addresses, disables environment proxies, refuses redirects, and rejects explicit `:cloud` and `-cloud` model identifiers before creating its HTTP client. Ollama documents both forms, including `gemma4:cloud` and `gpt-oss:120b-cloud`. These checks do not identify a hosted service hidden behind an arbitrary alias. They cannot prove what a service listening on localhost does upstream. Connect an actual local inference engine with downloaded weights, not a local proxy to a hosted API. See [Ollama cloud naming](https://docs.ollama.com/cloud) and the [cloud-suffixed model entry](https://ollama.com/library/gpt-oss:120b-cloud).

For Ollama, use downloaded local models. Its official FAQ documents `OLLAMA_NO_CLOUD=1` / the disable-cloud setting; apply the documented server-side control and restart Ollama as required. Installing the companion does not reconfigure an existing inference server. See [Ollama FAQ](https://docs.ollama.com/faq). Downloading models and installing software initially require access to their sources; this is separate from inference after setup.

The November 12 study used locked Qwen3.5 2B, 9B and 27B checkpoints and NVIDIA's 122B-A10B NVFP4 derivative through the pinned local vLLM image. The [version matrix](version-matrix.md) separates those measured configurations from the October 16 compatibility run. That earlier service advertised `nemotron-super-120b-fp4`; the alias alone does not establish an immutable model-weight identity. Neither study defines minimum reader hardware. The Ollama-native adapter's actual CPU integration evidence is recorded separately, including its semantic failures.

To evaluate local operation, inspect the served model identity, keep the engine itself local, and repeat a bounded inference test without internet access after setup. A loopback URL alone and a successful database test are insufficient evidence for end-to-end offline claims. Backups, exports, and screenshots remain files under your control; store real memory data privately.
